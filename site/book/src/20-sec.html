4. Защита данных и безопасность слабо

KMS и шифрование слабо

  • KMS — managed ключи в HSM. Типы: AWS owned (невидимы), AWS managed (aws/s3, бесплатно, ротация раз в год автоматически, политику не изменить), customer managed (CMK) (ты управляешь политикой; автоматическая ротация включается галочкой, раз в год).
  • Ключ привязан к Region. Для cross-Region — multi-Region keys или повторное шифрование при копировании.
  • Envelope encryption: KMS шифрует data key, data key шифрует данные. Прямой Encrypt в KMS ограничен 4 КБ.
  • Key policy обязательна у каждого ключа; доступ роли = key policy + IAM (или grants).
  • CloudHSM — выделенный HSM под твоим контролем (FIPS 140-2 Level 3), когда нужен полный контроль ключей или требование compliance. Для обычного шифрования хватит KMS.

ACM

Бесплатные публичные сертификаты с автообновлением, для ELB, CloudFront, API Gateway. Сертификат живёт в Region: для CloudFront — us-east-1; для ALB и regional API Gateway — в Region ресурса. На EC2 ACM-сертификат установить нельзя (для этого нужен собственный).

S3 security

  • Block Public Access (на аккаунт и bucket) — главный выключатель публичности.
  • ACL считаются устаревшими; включай Bucket owner enforced (ACL отключены).
  • Object Lock (WORM): Governance (можно обойти с правом) и Compliance (нельзя никому, включая root). Glacier Vault Lock — то же для vault.
  • MFA Delete при versioning: удаление версий только с MFA.
  • VPC endpoint + bucket policy с aws:SourceVpce — доступ только из твоей VPC.
  • Access Points — отдельная политика на приложение/команду вместо одной огромной bucket policy.
