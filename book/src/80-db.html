RDS и Aurora

  • Multi-AZ — синхронный standby в другой AZ, авто-failover, для HA (не для чтения). Read replica — асинхронная, масштабирование чтения, можно в другом Region.
  • Бэкапы: автоматические (до 35 дней, PITR) и ручные snapshots. Восстановление создаёт новый экземпляр.
  • RDS Proxy — пул соединений: спасает от шторма подключений Lambda, ускоряет failover.
  • Aurora: хранилище до 128 ТиБ, 6 копий в 3 AZ, быстрый failover; Aurora Serverless v2 — автоматическое масштабирование ёмкости; Global Database — репликация в другие Regions < 1 с, быстрый promote при аварии; Backtrack (откат во времени, MySQL).
  • Миграция provisioned Aurora → Serverless v2: добавить Serverless-экземпляр в кластер, failover на него.
  • IAM database authentication, шифрование при создании, SG на порт БД.

DynamoDB слабо

  • Режимы ёмкости: provisioned (+ auto scaling) и on-demand (непредсказуемо). Ключ: partition key (+ sort key). Горячий ключ — антипаттерн.
  • GSI (другой ключ, отдельная ёмкость), LSI (тот же partition key, только при создании таблицы).
  • DAX — in-memory кэш только для DynamoDB, микросекунды, без изменения кода приложения (вместо ElastiCache/API Gateway cache).
  • TTL — автоудаление; PITR — 35 дней; Global Tables — multi-Region multi-active.
  • DynamoDB Streams — упорядоченный поток изменений (24 ч); с Lambda (event source mapping) — реакция на новые/изменённые элементы.
  • Транзакции (ACID, TransactWrite), условные записи.

Redshift слабо

  • Колоночное хранилище OLAP (RDS = OLTP): отчёты, BI, PB. Кластеры (leader + compute nodes), Redshift Spectrum — SQL прямо по S3, Serverless.
  • HA: Multi-AZ (RA3); snapshots автоматические и ручные; DR при отказе Region → cross-Region snapshot copy.
  • Загрузка: COPY из S3 (параллельно), Kinesis Firehose → Redshift.
