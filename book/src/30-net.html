5. Сеть: VPC, DNS, CDN, балансировщики слабо

VPC: строительные блоки слабо

  • VPC — частная сеть в Region (CIDR /16–/28). Subnet — в одной AZ. 5 адресов в каждой подсети зарезервированы AWS.
  • Public subnet = route table с маршрутом 0.0.0.0/0 → IGW и у инстанса публичный/Elastic IP. Private — без маршрута в IGW.
  • IGW — двусторонний доступ в интернет для public subnet (горизонтально масштабируемый, без ограничений полосы).
  • NAT Gateway — исходящий IPv4 из private subnets. Живёт в public subnet (с Elastic IP), маршрут private → NAT. На AZ свой NAT для HA. Входящие соединения из интернета не пропускает.
  • Egress-only IGW — то же для IPv6 (исходящий да, входящий нет). У IPv6 нет NAT: адреса публичные.
  • Bastion host / SSM Session Manager — вход в private instances; Session Manager без открытых портов и ключей.
  • Flow Logs — метаданные трафика (в S3, CloudWatch); не содержимое.

Direct Connect

  • Private VIF — к ресурсам в VPC (через VGW или DX Gateway). Public VIF — к публичным сервисам AWS (S3). Transit VIF — к Transit Gateway.
  • Direct Connect Gateway — один канал к VPC в нескольких Regions.
  • Шифрование: VPN поверх DX (IPsec over public VIF) или MACsec.
  • Резервирование: второй DX (другая локация) или VPN как backup. Максимальная отказоустойчивость — 2 DX в 2 локациях.
  • Данные по DX: DataSync agent через service/VPC endpoint на private VIF (трафик не идёт в интернет).

VPC endpoints

  • Gateway endpoint — только S3 и DynamoDB, бесплатно, запись в route table.
  • Interface endpoint (PrivateLink) — ENI с private IP в твоей подсети для остальных сервисов и для чужих сервисов; платно.
  • PrivateLink также публикует твой сервис другим VPC без peering (за NLB).

Route 53 средне

  • Типы записей: A, AAAA, CNAME (не для корня зоны), Alias (бесплатно, для корня зоны, к ELB, CloudFront, S3 website, API Gateway; не к EC2 DNS).
  • Health checks + failover routing: primary/secondary. Health check умеет проверять endpoint, другие health checks (calculated) и CloudWatch alarm.

Route 53 только направляет DNSОн не обрабатывает данные, не видит HTTP-заголовки и не ускоряет трафик. Для «обработать рядом с пользователем» нужен edge compute.

CloudFront и Global Accelerator средне

  • CloudFront — CDN: кэш статики и динамики на edge. Origins: S3, ALB, EC2, любой HTTP. OAC (Origin Access Control) закрывает S3 так, чтобы доступ был только через CloudFront. HTTPS с ACM-сертификатом из us-east-1.
  • Приватный контент: signed URLs (отдельный файл, клиенты без cookies) или signed cookies (много файлов), + OAC на origin. S3 presigned URL обходит CloudFront.
  • Geo restriction, WAF, Shield, origin failover (origin groups), field-level encryption.
  • Edge compute: Lambda@Edge (viewer/origin request и response, полноценный код) и CloudFront Functions (только viewer, очень лёгкая логика: заголовки, редиректы). Response headers policy только добавляет/меняет заголовки ответа.
  • Global Accelerator — 2 anycast IP, трафик идёт по сети AWS, быстрый failover по health. Для TCP/UDP и не кэширует (игры, VoIP, статические IP, быстрый регион-failover). CloudFront — для HTTP-кэша.
⚠ Ты ошибался здесьГлобальный real-time clickstream, обработка у пользователя: CloudFront + Lambda@Edge + Kinesis + S3. Route 53 latency/geoproximity лишь направляет DNS; Athena не обрабатывает потоки.

API Gateway средне

  • Типы: REST (кэш, usage plans, API keys, WAF, валидация), HTTP (дешевле, проще, JWT), WebSocket. Endpoint: edge-optimized, regional, private.
  • Интеграции: Lambda, HTTP, сервисы AWS. Throttling, кэш ответов (TTL), stage variables, canary.
  • Custom domain для regional API: сертификат ACM в том же Region + Route 53 alias на домен API Gateway.
⚠ Ты ошибался здесьСертификат us-east-1 нужен только для CloudFront и edge-optimized. Для regional API Gateway — ACM в Region API.
