⚠ Ты ошибался здесь (дважды)Выдуманные типы: «Spot volumes» (Spot — модель покупки EC2) и «SR-IOV volumes» (SR-IOV — технология сетевых карт). gp3 не поддерживает Multi-Attach, а EBS не бывает multi-AZ. Верные описания: Provisioned IOPS = БД с высокой нагрузкой I/O, Magnetic = дёшево и редко.

EFS и FSx

  • EFS: NFSv4, Linux, POSIX, multi-AZ, классы Standard/IA/Archive (lifecycle). Режимы: General Purpose / Max I/O, throughput Bursting/Provisioned/Elastic.
  • FSx for Windows — SMB, AD, NTFS; FSx for Lustre — HPC/ML, быстрая работа с S3; FSx for NetApp ONTAP — мультипротокол (NFS/SMB/iSCSI); FSx for OpenZFS.
  • Триггеры: «Windows file share + AD» → FSx for Windows; «HPC / ML с S3» → Lustre; «Linux, много инстансов» → EFS.

  • Lifecycle — автоматический переход между классами и удаление; минимальные сроки хранения (IA 30 дней, Glacier 90, Deep Archive 180).
  • Glacier Expedited: для гарантии ёмкости купи Provisioned Capacity (иначе при пике запрос может отклониться).
  • Durability 11 девяток; versioning защищает от удаления/перезаписи; MFA Delete.
  • Производительность: 3500 PUT / 5500 GET в секунду на префикс; multipart upload (>100 МБ рекомендуется, >5 ГБ обязателен), Transfer Acceleration (загрузка через edge-локации с дальних клиентов), byte-range fetch.
  • Replication: CRR (другой Region: DR, задержка) и SRR (тот же Region: агрегация логов, другая учётка). Нужен versioning; реплицирует новые объекты.
  • Static website, event notifications (→ SNS, SQS, Lambda, EventBridge), S3 Select / Athena для запросов к данным.
  • Requester Pays: платит скачивающий.
