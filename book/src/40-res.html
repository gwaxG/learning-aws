6. Отказоустойчивость, decoupling и DR

Принципы HA

  • High availability = работает при отказе компонента: ≥ 2 AZ, нет single point of failure. Disaster recovery = восстановление после отказа Region/всего окружения.
  • Stateless приложение: сессии в ElastiCache/DynamoDB, файлы в S3/EFS — тогда инстансы заменимы.
  • Состояние внутри инстанса (EBS, instance store) мешает масштабированию и HA.

Auto Scaling Group

  • min / desired / max, размещение в нескольких AZ, замена нездоровых инстансов (EC2 и ELB health checks).
  • Launch template (версии) — новый AMI = новая версия шаблона; существующие инстансы обновляет instance refresh.
  • Политики: target tracking (держи метрику ≈ значению, проще всего), step, simple, scheduled (известная нагрузка), predictive. Метрики: CPU, ALBRequestCountPerTarget, длина очереди SQS на инстанс.
  • Lifecycle hooks — действие при запуске/остановке; warm pool — предподготовленные инстансы для быстрого старта; cooldown.

Disaster Recovery

RPO — сколько данных можно потерять (время). RTO — как долго можно быть недоступным. Чем меньше, тем дороже.

Какие данные как реплицировать

  • S3: Cross-Region Replication (нужен versioning; реплицирует только новые объекты, для старых — Batch Replication). Lifecycle в Glacier и копии на EC2 данные между Regions не переносят.
  • RDS: Multi-AZ = HA в Region (синхронный standby, авто-failover, не для чтения); cross-Region read replica → можно повысить (promote).
  • Aurora Global Database: репликация < 1 с, RTO < 1 мин при promote вторичного Region.
  • DynamoDB Global Tables: multi-Region multi-active. PITR и on-demand backups.
  • Redshift: автоматические snapshots в Region; для аварии региона — cross-Region snapshot copy.
  • EBS: snapshots (в S3), копирование между Regions и аккаунтами; DLM автоматизирует расписание.
  • Elastic Disaster Recovery (DRS): непрерывная репликация серверов в AWS, быстрое восстановление.
⚠ Ты ошибался здесь«Данные S3 переживают отказ Region» → CRR. Redshift DR при отказе Region → cross-Region snapshot copy. Правило: DR = отдельный Region, а Multi-AZ защищает только от отказа AZ.

AWS Backup

Единая политика (plans) для EBS, RDS, DynamoDB, EFS, FSx, S3, EC2 и других. Расписание, retention, cross-Region и cross-account копии, Vault Lock (WORM), отчёты. «Хранить бэкапы > 35 дней централизованно» → AWS Backup (у RDS нативно автобэкапы до 35 дней).

EBS: Data Lifecycle Manager или AWS Backup? «Автоматические snapshots EBS по расписанию» с минимумом настроек → DLM (бесплатно, по тегам). Много сервисов/аккаунтов или compliance → AWS Backup.
