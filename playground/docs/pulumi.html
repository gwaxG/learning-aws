1. What Pulumi is

Infrastructure as Code with general-purpose languages. You write a program that declares resources (VPC, RDS, S3…); the Pulumi engine compares it to the recorded state and calls the AWS APIs to make reality match. Comparable to CloudFormation/Terraform, but loops, functions and types are just Python.

2. Core concepts

ProjectA directory with Pulumi.yaml (name, runtime). Here: three-tier/pulumi.Projects
StackOne instance of a project (dev, prod), own config and state. Same code, different settings.Stacks
ResourceA cloud object declared in code, e.g. aws.rds.Instance. The first argument is the logical name; Pulumi adds a random suffix to the physical name unless you set it.Resources

3. Daily workflow

pulumi login                 # choose backend (pulumi login --local for a file backend)
pulumi stack init dev        # create a stack
pulumi config set aws:region eu-west-1
pulumi config set --secret dbPassword '...'
pulumi preview               # diff: what WOULD change (like terraform plan)
pulumi up                    # apply
pulumi stack output          # read exported values
pulumi refresh               # sync state with real cloud (after manual changes)
pulumi destroy               # delete everything in the stack
pulumi stack rm dev          # remove the empty stack

CLI reference: pulumi commands.

4. Setup for this repo

  • Installed: Pulumi CLI 3.134, AWS CLI 2 (default region eu-west-1), uv, Docker.
  • Credentials: Pulumi uses the standard AWS chain (env vars, ~/.aws, SSO). Verify with aws sts get-caller-identity. See AWS provider configuration and the AWS CLI authentication page.
  • Python project with uv: pulumi new aws-python, or create Pulumi.yaml with runtime: {name: python, options: {toolchain: uv}} (see Python in Pulumi).

Use a dedicated IAM user/role with least privilege for the playground, never the root account. Enable a AWS Budget alert before the first deploy.

5. Minimal AWS example

import pulumi
import pulumi_aws as aws

bucket = aws.s3.BucketV2("site")                       # logical name "site"
aws.s3.BucketPublicAccessBlock(
    "site-block", bucket=bucket.id,
    block_public_acls=True, block_public_policy=True,
    ignore_public_acls=True, restrict_public_buckets=True,
)

pulumi.export("bucket_name", bucket.bucket)            # Output[str]
pulumi.export("arn", bucket.arn)

Run pulumi preview first and read the plan: + create, ~ update, - delete, +- replace (destructive for databases!).

6. Patterns you will use

  • Config: cfg = pulumi.Config(); cfg.require_secret("dbPassword").
  • Dependencies: implicit via passing outputs (vpc_id=vpc.id); explicit via opts=pulumi.ResourceOptions(depends_on=[...]).
  • Protect critical resources: protect=True, retain_on_delete=True.
  • Import existing resources: pulumi import (guide).
  • Pass outputs into strings: pulumi.Output.concat("postgresql://", user, "@", db.address).
  • Testing: unit tests with mocks (unit testing).
  • Shipping files: aws.s3.BucketObjectv2 with pulumi.FileAsset/FileArchive (assets & archives).

8. Pitfalls & cost hygiene

  • Always pulumi destroy after a session. The usual leaks: NAT Gateway (~$0.045/h + data), ALB, RDS, Elastic IPs, CloudFront logs, ECR images.
  • Replace vs update: some property changes force replacement; on RDS that means a new empty database. Read the preview.
  • Secrets: never put plain passwords in code or Pulumi.<stack>.yaml; use --secret. Secret outputs stay encrypted in state; the state backend still needs protecting.
  • Manual console changes cause drift; run pulumi refresh and review.
  • Stuck deletes: non-empty S3 buckets (force_destroy=True for playgrounds), VPCs with leftover ENIs, security groups still referenced.
  • Resource names: let Pulumi auto-name unless a name is required to be stable; fixed names block replacements.
