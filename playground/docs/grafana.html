Grafana for the three-tier stack

How to visualise the stack in playground/three-tier with Grafana. Nothing here is deployed by Pulumi yet; this is the configuration guide. Related: ADR 0005 (CloudWatch), Pulumi guide.

1. What Grafana reads

Everything the stack produces already lands in CloudWatch, so the data source is CloudWatch (not Prometheus) and nothing has to be installed in the stack.

SignalWhereGrafana query type
ALB requests, 5xx, latency, healthy hostsnamespace AWS/ApplicationELB, dimensions LoadBalancer, TargetGroupCloudWatch Metrics
ECS service CPU / memoryAWS/ECS, dimensions ClusterName, ServiceNameCloudWatch Metrics
Task-level detailECS/ContainerInsights (when containerInsights is on)CloudWatch Metrics
RDS CPU, connections, free storageAWS/RDS, dimension DBInstanceIdentifierCloudWatch Metrics
Application logslog group from pulumi stack output log_groupCloudWatch Logs (Logs Insights)
Alarm statesthe 6 CloudWatch alarmsGrafana alert list panel

Dimension values and metric names are the same ones used by the dashboard widgets in pulumi/__main__.py.

3. Option A: local Grafana

  1. Run it (PowerShell): 
    docker run -d --name grafana -p 3000:3000 `
  -v ${env:USERPROFILE}\.aws:/usr/share/grafana/.aws:ro `
  -e AWS_PROFILE=default grafana/grafana-oss
    Open http://localhost:3000 (first login admin / admin, then change it). The mounted .aws folder lets the data source use your AWS CLI credentials.
  2. Add the data source: Connections → Data sources → CloudWatch. Authentication provider AWS SDK Default, default region eu-west-1. Save & test must succeed.
  3. Permissions: the IAM user/role behind those credentials needs the managed policies CloudWatchReadOnlyAccess and CloudWatchLogsReadOnlyAccess (least privilege: read only). Prefer a dedicated read-only user created with Pulumi over reusing admin keys.
  4. Build panels
    • Metrics: choose namespace, metric name, dimensions and statistic (Sum for counts such as RequestCount, Average for CPU).
    • Logs: query type Logs, pick the log group, then for example fields @timestamp, @message | sort @timestamp desc | limit 100.
    • Variables: add dashboard variables (for example ClusterName from the dimension-values query) so one dashboard works for every stack.
  5. Alerts (optional): Grafana can alert on the same queries, but it duplicates the CloudWatch alarms. Keep one source of truth, normally CloudWatch alarms + SNS.
  6. Stop it: docker rm -f grafana. Dashboards live in the container unless you add -v grafana-data:/var/lib/grafana.

4. Option B: Amazon Managed Grafana

  • Pulumi resource aws.grafana.Workspace with account_access_type="CURRENT_ACCOUNT", authentication_providers=["AWS_SSO"], permission_type="SERVICE_MANAGED", data_sources=["CLOUDWATCH"].
  • Login goes through IAM Identity Center; assign users with aws.grafana.RoleAssociation (ADMIN / EDITOR / VIEWER).
  • With service-managed permissions AWS creates the workspace IAM role with CloudWatch read access, so the CloudWatch data source needs no keys.
  • Docs: What is Amazon Managed Grafana, permissions.

5. Option C: Grafana on Fargate (not recommended here)

Needs a second task definition and service, EFS (aws.efs.FileSystem) so dashboards survive restarts, a task role with the CloudWatch read policies (different from the execution role, see the comments in __main__.py), and a way to reach it (another ALB listener or CloudFront behavior with authentication). Provision the data source with a file in /etc/grafana/provisioning/datasources/:

apiVersion: 1
datasources:
  - name: CloudWatch
    type: cloudwatch
    jsonData:
      authType: default        # uses the task role
      defaultRegion: eu-west-1

6. PostgreSQL data source

The database is in private subnets and db-sg only accepts the app, so a laptop Grafana cannot reach it. Options:

  • CloudWatch metrics only (connections, CPU, storage). Enough for health and capacity.
  • Grafana inside the VPC (option C) with a security-group rule allowing it on 5432.
  • SSM port forwarding through a small instance in the VPC (remote port forwarding); adds a resource to the stack.

If Grafana queries application tables, create a read-only PostgreSQL user for it; never reuse the app user.
